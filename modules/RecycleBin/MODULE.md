# RecycleBin

- `RecycleBin_ListView_Model` owns deleted-record lists and counts. Its factory builds a `Core_QueryGenerator_Model` for the source module on its "All" filter; `parseAdvFilterList()` wraps OR groups inside the surrounding constraints. List and count both take the normal query and rewrite `vtiger_crmentity.deleted = 0` to `deleted = 1`; keep that rewrite and the source-module permissions in both paths.
- Recycle Bin list access follows the module permission. Every restore, permanent-delete and empty-bin `RecycleBinAjax` operation is administrator-only; non-admin users do not receive these action links. The source-module list excludes ProjectMilestone, ModComments, Integration, PBXManager, Dashboard, Home and non-entity modules. Mass operations must send an explicit selection state; "select all" also sends excluded IDs and search parameters and the action verifies that the selected view belongs to the source module.
- Permanent deletion (`RecycleBin_Module_Model::deleteRecords()` and `emptyRecycleBin()`) removes the `vtiger_relatedlists_rb` and `vtiger_modtracker_basic` rows and the `vtiger_crmentity` rows of deleted records. `deleteRecords()` first restricts requested IDs to `vtiger_crmentity.deleted = 1` and the requested source module, and also deletes related ModComments. `deleteFiles()` removes the target records' attachment relations, but removes attachment metadata and physical files only after no CRM record, user image or MailManager message references the attachment; paths are resolved through `Core_Storage_Model`, so legacy relative and configured absolute storage paths both work.
- `RecycleBin_Install_Model` registers a standard module without owned tables.
