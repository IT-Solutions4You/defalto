# Import

- `Import_Install_Model` owns the tables `vtiger_import_locks`, `vtiger_import_queue` and `vtiger_import_maps` and registers the `Scheduled Import` cron (900 s, handler `cron/modules/Import/ScheduledImport.php`, which calls `Import_Data_Action::runScheduledImport()`). Import actions own the queue and lock rows and the per-user import tables (`vtiger_import_<userid>`, prefix from `Import_Config_Model`).
- `Import_Config_Model` holds the limits: `importBatchLimit` 250 records per request, `immediateImportLimit` 5,000 and `importPagingLimit` 10,000. `Import_Main_View::queueDataImport()` schedules an import through cron only when the record count is greater than 5,000, so 5,000 runs immediately and 5,001 is scheduled. Immediate imports run in the browser, 250 records per request.
- Readers in `readers/` handle `csv`, `vcf` and `ics`; any other type uses `Import_FileReader_Reader`.
- `Import_ListView_Model` owns the imported-record list and count. Its factory builds a `Core_QueryGenerator_Model` for the source module. The list always restricts to the current user's imported records, meaning rows of that user's import table whose status is neither failed nor skipped and that have a record id. `Core_QueryGenerator_Model::parseAdvFilterList()` wraps OR groups inside this restriction, and groups without columns are dropped. `Import_List_View::getPageCount()` and `getListViewCount()` pass only the quick-search key and value to the count, not advanced conditions.
- Saved mappings (`vtiger_import_maps`) record whether they were saved for a file with a header row. `Import.js` `loadSavedMap()` matches by column name for header maps and by column position otherwise, and fills only columns that exist in the map and whose field is still available.
- Validate list/count grouping including OR and empty groups and lint `models/ListView.php`. For routing changes verify the 5,000 and 5,001 record boundaries and PHP request duration with a representative import.
