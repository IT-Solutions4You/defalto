# Layout Editor

Administrators use the module Layout Editor to add fields and arrange them in blocks. Choose the module, open the desired block, select **Add custom field**, and choose a field type and label. Existing profile and record access rules still apply to the resulting field.

## Checklist fields

For modules with CRM records, choose **Checklist** to add one checklist field to any ordinary block. A separate Checklist block is not needed. Each checklist field keeps its own item text and completion states, so a record can contain multiple independent checklist fields.

The field has the same borderless checklist interface in record details and editing. Users can add, rename, complete and remove items when they can edit the record and the field. Otherwise the checklist is read-only. On a new record, users can prepare item texts before saving; marking items complete becomes available after the first save.

## Link Settings

Open **Settings → Module Manager → Link Settings** and select a module. Detail and List view appear together on one page, each with three boxes: Basic buttons, Special actions and More. All six boxes remain visible even when empty. The detail groups correspond to DETAILVIEWBASIC, DETAILVIEWADVANCED and DETAILVIEW. The list groups correspond to LISTVIEWBASIC, LISTVIEWMASSACTION and LISTVIEW; Import is included from the module header actions.

The overview combines stored links, missing installation declarations and actions generated by the module detail/list models. Installation instructions that remove obsolete links are excluded from default definitions. Only these six action groups are included. Widget links, related lists, navigation tabs and administrative settings links are excluded. Standard Edit, Delete, Duplicate, generic Add record and tag actions are also excluded. Module-specific actions, such as adding a project task or milestone, remain visible. Code-generated actions use current module settings and administrator permissions without loading a specific CRM record; actions conditional on existing record values can differ on the actual record.

Each item shows its translated action name in the selected application language, including stored links and code-generated actions. Select the translated label with its disclosure arrow to inspect the destination, Quick Create/full form destinations when provided, and other link information with translated field labels. Supported font icons appear as visual previews; unknown icon values remain text. A green check marks a link declared by the current installation configuration and already installed. A red check marks a declared link that is not yet installed. The tooltip identifies its installation state. Code origin alone does not mark a link as Default.

Only stored links outside the current installation declarations have **Actions → Delete**. Default links cannot be deleted, whether installed or missing, because updates can register them again. After confirmation, the matching link registration is removed without deleting CRM records or documents. Identical registrations with the same type, name and destination are removed together. The row disappears unless installation settings or application code still define it, in which case its read-only definition remains. Links are never removed automatically.

Administrators can open **Settings → Module Manager → Link Settings** directly. Choose a module to see its registered Detail and List actions. Link Settings is a standalone editor, alongside Widget editor, and is no longer a Layout Editor tab. Changing the module refreshes the action list while keeping the editor open.
