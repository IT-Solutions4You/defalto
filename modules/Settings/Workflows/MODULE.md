# Workflow management

- This Settings module manages definitions executed by `modules/com_vtiger_workflow`; it is not the task execution owner.
- `models/Record.php::getEditViewUrl()` provides the base workflow edit URL. The current editor requires `mode=V7Edit`, as appended by `ListViewContents.tpl`; without a mode, the controller enters the legacy `step1()` flow. Audit UI links must include this mode and enforce Settings access on the server.
- Workflow definitions and task persistence use the legacy workflow manager and task manager. Execution entry points and save-event boundaries are documented in `modules/com_vtiger_workflow/MODULE.md`.
- Modern editor conditions use `groupid=0` for All and `groupid=1` for Any; `joincondition` connects rows and `groupjoin` connects groups. List display uses the same normalized groups as the editor, not `groupjoin`.
- `Condition_Model::getEditableConditions()` normalizes homogeneous AND/OR groups joined by AND, including legacy flat lists and null values. It rejects mixed operators, interleaved groups, incompatible group merges, and empty condition placeholders. It preserves condition values and value types; normalization is idempotent.
- `Workflow_Model::migrateConditions()` restores legacy conditions from `registerWorkflowTasks` during module data migration. Match by both module and workflow name, and skip duplicate definitions, duplicate stored matches, missing matches, or unsupported defaults. Preserve rows marked 6 with complete modern group metadata; a marker alone does not prove modern format. Update only `test` and `filtersavedinnew`, using a conditional write against the previously read values to preserve concurrent edits. Repeated migration is idempotent; user workflows without matching definitions are untouched.
- `Record_Model::isFilterSavedInNew()` normalizes compatible existing conditions in memory for editing; persistence occurs only through the normal save flow. Unsupported conditions retain the legacy choice. Recreate reveals blank criteria without selecting fields automatically, and toggling back preserves the draft. Use existing conditions reads persisted conditions on the server.
- Saving editor groups derives operators and group IDs from the group containers. Empty All groups do not generate a false placeholder condition, so Any-only workflows remain executable. Validate normalization with the real `VTJsonCondition` evaluator, editor/save round trips, installation definitions, PHP lint, and the existing ScriptsValidator.
- `AdvanceFilter.tpl` renders only saved criteria in each visible condition list. Empty groups retain Add Condition and the hidden `.basic` row used for cloning, without creating a visible placeholder. An empty comparison value is valid for operators such as `is added` and must not be confused with a missing condition.
- `workflowname` is the workflow name and `summary` is its description; the legacy record model `getName()` returns `summary`. Task `summary` is its user-supplied title/description; its task type provides the action label.
- The workflow name column renders the description below the name using `small text-secondary`. The list query fetches `summary` separately from visible fields; empty descriptions render no extra line.
- The list template places the combined creator/time column last, after Actions, in both the header and each data row.
- The list's `creator` column displays the user label with `createdtime` below it; the list query selects the timestamp separately from visible fields. `Record_Model::getDisplayValue()` displays the active administrator from `Users::getActiveAdminId()` when the stored creator is missing or empty, without changing persisted provenance. It formats database timestamps through `Vtiger_Datetime_UIType` in the current user's time zone and hour format; missing timestamps display an em dash. Templates escape these display values as plain text; do not convert the stored timestamp before formatting it.
- The list renders `summary` as escaped plain text with the existing list-length limit. `Workflow_Model` owns new definition inserts through `Core_DatabaseData_Model`; `Record_Model::createTables()` adds nullable `createdtime` and `creator` columns through the existing `Core_CreateTables_Config` installation/update flow. Existing definitions retain null metadata. Creation records the current instant in the database time zone and the authenticated execution user's ID (null without a user); updates preserve both values, and imports/copies receive fresh metadata.
- `history_task_id` deep links are handled by `Edit.js::showHistoryTask()` after the action container loads. Only an existing task link in the current workflow can open, through the existing overlay handler and its V7 URL; the task opens once per editor instance.
- `resources/Edit.js::loadFieldSpecificUi()` uses date display values only for `rawtext`. `Workflows_Date_Field_Js` in `resources/AdvanceFilter.js` displays expressions and field references from their serialized mapping value and assigns input values through the DOM; never date-format expression source or prefer an empty display value over it. Template input values must be HTML-escaped to preserve quoted expressions.
