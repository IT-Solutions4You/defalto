# Customer Portal

- `modules/CustomerPortal/api.php` authenticates portal requests (`authenticatePortalUser()`) and dispatches the `apis/<Operation>.php` controllers. Portal contacts run web-service queries through the active CRM administrator (`Users::getActiveAdminId()`), so CustomerPortal must enforce contact and account isolation itself before executing a query.
- `SaveRecord` must authorize every existing `recordId` before retrieval or update. The active portal contact may update only its own Contacts record, its parent Accounts record, records accepted by `CustomerPortal_API_Abstract::isRecordAccessible()`, or records exposed through an accessible `parentId` under the same relation rule as `FetchRecord`. The client-supplied `values` payload must never select or replace the persisted record ID; only the authorized request `recordId` may identify an update target. Empty IDs and exact `<entityTypeId>x0` placeholders are create requests and must use the module create permission.
- Fetch and export equality filters are built only by `CustomerPortal_Utils::getVtqlFilterConditions()` (used by `FetchRecords` and `ExportRecords`). Field names must be active portal fields and values must be scalar VTQL literals. Only `AND` is supported because the flat VTQL grammar cannot safely scope `OR` conditions beneath the mandatory relation or publication predicates.
- Filter literals use doubled apostrophes for VTQL and reject backslashes, so differences between VTQL and database string parsing cannot restore query syntax.
- Image encoding (`CustomerPortal_Utils::getEncodedImage()`) and file downloads (`DownloadFile`) resolve `vtiger_attachments` rows through `Core_Storage_Model::getAttachmentFilePath()`, which supports legacy relative paths and configured absolute storage paths. Never prepend `root_directory` to an attachment path without checking whether it is absolute.
- Validate with `php -l` on touched PHP files. For save changes, verify that an accessible existing record can still be updated, an unrelated record is rejected before `vtws_retrieve()` or `vtws_update()`, and a create request cannot become an update through `values.id`. For filter changes, exercise FetchRecords and ExportRecords with ordinary filters, apostrophes, rejected backslashes and rejected non-`AND` operators.
