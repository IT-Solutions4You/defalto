# Webforms

## Ownership and entry points

- `modules/Webforms/capture.php` is the public submission entry point generated by the Settings Webforms UI. It changes to the application root and must load `config.php` before framework and module files so database globals and application configuration are available.
- `Webforms_Model` owns persisted form definitions, selected fields, defaults, round-robin assignment, and document creation. `Webforms_Field_Model` owns the configured field metadata and required-value decision.
- `modules/Settings/Webforms` owns administration and generated form markup; the submitted record is created through `vtws_create()` as the active administrator.

## Submission invariants

- A configured required field accepts `0` as a value but rejects `null`, an empty string, or an empty array.
- Before record creation, every configured target field must pass `Vtiger_Util_Helper::validateFieldValue()`. This keeps webform validation aligned with normal record saves and rejects values unavailable in picklist and multipicklist fields.
- Webform defaults participate in the same server-side validation as submitted values. Client-side `required` attributes are only a convenience and are not a security or integrity boundary.

## Persistent data and contracts

- Definitions are stored in `vtiger_webforms`; selected field settings are stored in `vtiger_webforms_field`.
- Public callers submit `publicid`, `urlencodeenable`, and configured field names to `modules/Webforms/capture.php`. Success creates the target record, optional Documents relations, and then returns JSON/JSONP or redirects to the configured return URL.

## Validation

- Run `php -l modules/Webforms/capture.php` and `php -l modules/Webforms/model/WebformsFieldModel.php`.
- Submit a valid form and confirm the target record is created; submit an empty required field and unavailable picklist or multipicklist values and confirm no record is created and an error response is returned.
