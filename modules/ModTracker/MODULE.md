# Record audit ownership

- `ModTrackerHandler.php` handles before-save, final-save, delete, and restore events. Before-save registers an independent audit baseline; final-save delegates to `ModTracker_History_Helper::saveHistory()`. Workflow condition deltas remain separate.
- `models/Install.php` owns event registration and the schema for `vtiger_modtracker_basic`, `vtiger_modtracker_detail`, `vtiger_modtracker_tabs`, and `vtiger_modtracker_relations`.
- `ModTracker_Basic_Model::saveHistory()` is the shared save-history writer; `ModTracker_Detail_Model` writes field details. Deltas use `VTEntityDelta::getDataDelta()` and skip `modifiedtime`, preserving the existing comparison semantics.
- Table-backed models use `getTable($this->table, $this->tableId)` for CRUD, following the shared model pattern; do not set table metadata in their constructors. Field detail inserts are owned by `ModTracker_Detail_Model::saveFieldChange()`.
- `ModTracker_Basic_Model::getModTrackerBasicTable()` provides the configured basic-history table model used by the history writer.
- `ModTracker_Detail_Model::getModTrackerDetailTable()` provides the configured detail-history table model used by `saveFieldChange()`.
- Basic history stores record, module, user (`whodid`), time, status, and nullable `workflow_id`/`task_id`; detail rows store previous and current field values. Old rows retain null provenance. The install model creates/migrates columns before registering handlers on install/update/enable. ModTracker overrides the inherited extension version to version its schema independently.
- `models/Record.php::getUpdates()` supplies record history to `Vtiger_Detail_View`. The record Updates UI is rendered by `layouts/d1/modules/Vtiger/RecentActivities.tpl`; the similarly named ModTracker template is a placeholder.
- `ModTracker_History_Helper::processTask()` scopes workflow/task identity with `try/finally` in all three execution paths and flushes pending initiating saves before task execution. `saveRecord()` wraps the existing `saveentity()` path, without invoking workflow events. WeakMap audit baselines advance after each history write to prevent duplicate outer-save entries. Disabled ModTracker/modules remain untracked.
- `Workflow.tpl` adds provenance to create/update entries. Only administrators retrieve the current workflow name and edit link; deleted workflows retain their numeric ID without a link. Updates sort by time and descending history ID to order writes within the same second.
- Workflow and task lookup caches are protected instance properties on `ModTracker_Record_Model`, keyed by workflow ID and workflow/task ID respectively. Cache null results with `array_key_exists()` and check administrator access before reading cached metadata. Separate history model instances do not share these caches.
- Workflow history links append `mode=V7Edit` to the Settings workflow model's base edit URL, matching the workflow list and opening the current editor.
- Workflow entries show only `workflowname` as a Bootstrap dropdown trigger; `summary` is the workflow description, despite the Settings model's legacy `getName()` accessor returning it. The dropdown contains the actor and administrator-only current workflow/task metadata and links. Task lookups verify both task ID and workflow ID. Deleted definitions fall back to stored IDs; metadata is current, not a historical snapshot.
- Task links open the full workflow editor with `history_task_id`; its existing task overlay is initialized after the action list is loaded. Do not navigate directly to an overlay-only task view.
- Dropdown navigation links are grouped below a divider and use Bootstrap dropdown-item styling with action icons and trailing information icons. The trigger also uses an information icon. The menu has a fixed 24rem width capped to the viewport, with long text wrapping.
- Preserve user identity separately from automation provenance. Existing history is also consumed by the update APIs in `ModTracker.php`.
- The shared Vtiger history template identifies workflow create/update entries with a `fa-cogs` timeline icon, overriding the actor avatar.
- Validate PHP changes with lint and manually verify history, pagination, tracking-disabled modules, and update API compatibility.
