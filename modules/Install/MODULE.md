# Installation and data migration

Install is the setup wizard and the shared installation/migration helpers. Licenses, updates and extensions belong to Installer, not to this module.

- `Install_InitSchema_Model::initialize()` runs a fresh installation. It creates the base tables, calls `Install_Utils_Model::installTables()`, creates the default roles and profiles, then calls `initProfileModulePermissions()`. `upgrade()` runs the legacy schema files, `installMigrations()`, `saveSMTPServer()` and `saveInstallerLicenses()`.
- `Install_Utils_Model::installTables()` calls `installTables()` on every `<Module>_Install_Model` except `Core`, and returns early when the tables are already installed. `migrateTablesData()` does the same with `migrate()`; `Migration_Index_View::migrateData()` is its caller. A failing module migration is logged and does not stop the others.
- Module tables are installed before the default profiles exist. `initProfileModulePermissions()` then adds only the missing `vtiger_profile2tab` rows and the standard entity-action rows in `vtiger_profile2standardpermissions` (Save, EditView, CreateView, Delete, index, DetailView). It is idempotent; migration `20261016200000` reuses it.
- The dispatcher calls only the module-specific `migrate()`. A module that owns workflow defaults (Accounts, Contacts, HelpDesk, Potentials) calls the inherited `Core_Install_Model::migrateWorkflowConditions()` from its own `migrate()`; workflow regeneration is not a global hook.
- `InitSchema_Model::registerTrashWorkflowTask()` registers only the `VTTrashTask` task type, and only when it is missing. Initial setup and migration `20260915120000` share it. It does not register events, change the queue schema, activate workflows or delete records.
- `saveInstallerLicenses()` combines the `licenses` array with the legacy singular `license` value, trims and deduplicates scalar keys, and delegates each activation to `Installer_License_Model::activate()`. Invalid new keys are not persisted. Do not add other license persistence to Install.
- Validate changes with PHP lint and manual checks of migration ordering and idempotence. A workflow migration must preserve modern conditions, task definitions, status, scheduling and creation metadata.
