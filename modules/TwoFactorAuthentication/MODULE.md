# TwoFactorAuthentication

- The login modifier `TwoFactorAuthentication_LoginAction_Modifier` starts the pending challenge only after the Users password check succeeds and delays `Users_Authentication_Model::completeLogin()` until the second factor is verified.
- `TwoFactorAuthentication_Service_Helper` owns the login challenge state machine in `$_SESSION['two_factor_authentication']`, email codes, TOTP enrollment and verification, backup-code verification, lockouts, and the logged-in self-service enrollment session.
- A user with a persisted method must complete that method for the current login. `beginChallenge()` narrows the session's allowed methods to the persisted method, `chooseMethod()` validates both the server-side snapshot and the current persisted method so stale sessions cannot bypass it, and `switchMethod()` cannot alter a challenge locked to one method. Changing methods remains available after successful login through the My 2FA self-service flow.
- Users without a persisted method may choose from the globally allowed methods during their first protected login. Their choice locks the pending challenge to that method. TOTP is persisted only after its first valid application code, and login-time TOTP enrollment requires the versioned challenge state to confirm that no method existed when the challenge began.
- A persisted method that is no longer globally available, or persisted TOTP without a completed enrollment, must not fall back to another method or start enrollment before authentication. The user may use an existing backup code where available; otherwise an administrator can reset or update the user's 2FA configuration.
- Persistent data is owned by `TwoFactorAuthentication_Config_Model`, `TwoFactorAuthentication_User_Model`, `TwoFactorAuthentication_BackupCode_Model`, and `TwoFactorAuthentication_EmailTemplate_Model` for the `df_two_factor_*` tables installed by `TwoFactorAuthentication_Install_Model`.
- The pre-login challenge UI is owned by `TwoFactorAuthentication_Challenge_View`, `TwoFactorAuthentication_Verify_Action`, and `layouts/d1/modules/TwoFactorAuthentication/Challenge.tpl`. Logged-in user and administrator pages live under `modules/Settings/TwoFactorAuthentication` and its matching layout resources.
- Validation: run `php -l` on touched PHP files; exercise an existing email user's direct `switch` and forged `choose=totp` requests, a normal email-code login, a first-time method choice, and the logged-in My 2FA method-change flow.
